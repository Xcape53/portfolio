How I build with AI

I use Claude Code and Codex every day. The models write most of the code. I decide what gets built, how it splits into parts, and what has to be true before anything is merged. JobManager and this site were built this way.

For anything bigger than a quick fix I follow the workflow below. The example is a real kind of task: adding one more job portal to JobManager.

  1. G1Gather requirements

    Which fields the new source must deliver, how often it updates, which filters it feeds. I write these down as checks that can pass or fail.

    me
  2. G2Study the system

    Read-only agents map the existing scrapers, the shared normaliser and the tests, then report back in short summaries.

    research agents, read-only
  3. G3Check what already exists

    Is there an official API, a public feed or a maintained library? Scraping comes last, after the portal's terms allow it.

    research agent + me
  4. G4Write the plan

    Modules, data contracts, the files each part may touch and how each part is tested. No code is written until I approve it.

    human approval
  5. G5Split into blocks

    The plan becomes independent tasks that never edit the same files, so they can run in parallel without conflicts.

    me
  6. G6Dispatch agents

    One coding agent per block, each on its own branch, in a sandbox, allowed only the commands its task needs.

    coding agents
  7. G7Independent review

    A separate agent with a fresh context compares each diff with the plan and runs the tests. A block that fails goes back to step 06 with the reviewer's notes, and the loop repeats until it passes.

    reviewer agent
  8. G8Merge and watch

    I read the final diff, run it on real data and merge it. Larger changes get a backup first, so there is always a way back.

    human approval

Where it can go wrong

Agents make mistakes, and they can be misled. Prompt injection has no complete fix yet, so I treat web pages, issues and tool output as untrusted data. Secrets stay out of prompts and repo files, I check that a package an AI suggests actually exists before installing it, and I only add skills or MCP servers whose source I have read.

At a company, personal data and the employer's code would go only into tools the company has approved. GDPR applies to anything sent to a model provider, the EU AI Act adds its own duties, and the OWASP Top 10 for LLM and agentic applications is the checklist I review against. Whoever typed a line, I am responsible for it once I merge it.

I haven't run agents in a company's production environment yet. This is how I work on my own projects, based on Building effective agents, Claude Code best practices and the OWASP GenAI Security Project.
